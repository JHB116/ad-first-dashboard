# 광고 신규 실적 대시보드

LF몰 **광고유형별 신규(가입)·첫구매 실적**을 깊게 보는 대시보드다. 전체 채널 관점의 [첫구매 실적 대시보드](https://github.com/ryunj/first-dashboard)와 같은 틀(정적 HTML 한 장 + Streamlit 래퍼 + 브라우저에 여는 백업 파일)을 쓰고, 광고 실적만 유형 → 매체 → 캠페인 단위로 파고든다.

**저장소에는 실적 데이터가 없다.** 원천 파일로 백업(`.json.gz`)을 만들어 화면에서 연다. 열어 둔 데이터는 그 브라우저(IndexedDB)에만 저장된다.

## 원천 형식

| 원천 | 형식 | 비고 |
|---|---|---|
| **로우 시트 xlsb** | 시트 이름 `로우`, 첫 행 헤더 (`기간_일자`, `구분_광고유형`, `구분_채널`, `구분_매체명`, `구분_비용출처`, `구분_캠페인`, `구분_하위캠페인`, `구분_브랜드/기획전`, `구분_디바이스`, `지표_광고비`, `지표_UV(전체)`, `지표_UV(비회원)`(또는 `지표_비회원UV`, 없으면 `지표_UV(회원)`으로 계산), `지표_가입회원`, `지표_총결제고객수`, `지표_총결제거래액`, `지표_총결제고객수(첫구매)`, `지표_총결제거래액(첫구매)`, `지표_순결제고객수(첫구매)`, `지표_총결제고객수(윈백)`, `지표_당년신규순결제고객수`, `지표_당년신규순결제거래액`) | 일일보고서 xlsb 전체든 로우 시트만 뽑은 파일이든 같다. 다른 컬럼은 무시. 기간을 나눈 파일 여러 개 가능 |
| **사이트검색 리포트** | 숨김 시트 `숨김_AF코드성과`(로우 시트가 없는 파일이면 자동으로 알아본다), 헤더는 로우에서 `구분_` · `지표_`를 뺀 이름 + `날짜` · `보고_캠페인` · `보고_그룹` · `브랜드` · `카테고리` · `구분` | raw 폴더에 로우와 함께 넣거나 bat 에 같이 끌어다 놓는다. 리포트가 있는 날짜는 사이트검색광고를 리포트 값으로 바꾼다(로우 값 버림 · 중복 없음). 화면 '집계 기준'에 날짜 범위와 로우 vs 리포트 합계 표시. 드릴다운 차원에 보고 캠페인 · 보고 그룹 · 카테고리 · 구분(소재) 추가 |

원천은 로우(+ 사이트검색 리포트)다. 첫구매 실적 대시보드의 원천 형식과는 무관하다. 계절 비교(전년 같은 구간)는 로우에 그 해 데이터가 있어야 계산된다.

연도에 따라 컬럼이 조금 달라도 된다(예: 2024년 원천에는 `순결제고객수(첫구매)` · `당년신규순결제고객수/거래액` · `총결제고객수(윈백)`이 없다). **없는 지표는 0이 아니라 '데이터 없음'으로 기록**하고, 그 기간이 낀 값 · 전년비는 `–`로 표시한다(화면 '집계 기준'에 지표 · 기간 표시). 다른 지표는 그대로 쓴다.

## 데이터 올리기 · 갱신

대시보드는 넣은 백업을 **이 브라우저에 기억**하고, 새로 넣는 백업을 **날짜 단위로 합친다**(새 백업에 있는 날짜는 교체, 나머지 날짜는 그대로). 원천(xlsb · csv)은 PC에서 `make_backup.bat` 으로 백업을 만들어 넣는다 — 서버에는 아무것도 올리지 않는다.

### PC에서 백업 만들어 끌어다 놓기

**처음 한 번 (2024년)**
1. 이 저장소를 내려받는다(GitHub → Code → Download ZIP → 압축 풀기, 또는 `git clone`).
2. `make_backup.bat` 을 더블클릭하면 같은 폴더에 `raw` 폴더가 생기고 열린다. 거기에 **2024년 csv**를 넣는다.
3. `make_backup.bat` 을 다시 더블클릭 → 필요한 패키지를 설치하고 `backup` 폴더에 `광고신규대시보드_백업_YYYYMMDD.json.gz` 를 만든 뒤 폴더를 연다.
4. 그 파일을 대시보드 화면에 끌어다 놓는다. 이제 대시보드가 2024년을 기억한다.

**매일 (2025-26 xlsb)**
1. 아침에 새로 만든 2025-26 xlsb 파일을 **`make_backup.bat` 아이콘 위에 끌어다 놓는다**(파일 위치는 어디든 상관없다). 그 파일만 읽어 백업을 만든다.
2. 열린 `backup` 폴더의 가장 최근 파일을 대시보드에 끌어다 놓는다 → 2025-26 날짜만 교체 · 추가되고 2024년은 그대로.

- 대시보드 프로그램이 바뀌었으면(빌드 로그 첫 줄 `build_data.py 버전` 이 안내와 다르면) **`update.bat` 더블클릭** → 최신 파일로 바뀐다. 처음 한 번은 GitHub 에서 `update.bat` 을 받아 대시보드 폴더에 둔다.
- 2024년 csv는 처음 한 번만 읽고 결과를 `data\cache` 에 저장해 두므로, 매일은 2025-26 xlsb만 새로 읽는다.
- 직접 실행: `python build_data.py`(raw 폴더 전부) · `python build_data.py --row a.xlsb b.csv`

### 공통

- 다른 PC · 브라우저로 옮기거나 보관하려면 대시보드 오른쪽 위 **백업 내려받기** → 다른 곳에서 **백업 파일 열기**.
- 처음부터 다시 넣으려면 **데이터 지우기** 후 넣는다. 브라우저 사이트 데이터를 지우면 저장된 데이터도 지워진다.
- csv는 엑셀에서 저장한 그대로(UTF-8 · CP949, 쉼표 · 탭) 읽는다. `기간_일자`는 2024-01-01 · 2024.01.01 · 20240101 · 엑셀 일련번호 모두 된다.
- 원천은 2만 행씩 나눠 읽고 필요한 컬럼만 바로 합산한다(메모리 절약).

## 화면

| 메뉴 | 내용 | 출처 |
|---|---|---|
| **추이** | 실적 요약 타일(상단에서 고른 비교 하나) → 흐름 → 실적 표(연도별 행 / 엑셀형, 전년비 · 전전년비, CSV). 흐름은 기준 연도(파란 실선) · 전년(진회색 실선) · 전전년(회색 점선)을 1~12월(주별 · 일별은 364일 전 같은 요일) 축에 겹쳐 그림(범례의 연도를 눌러 그래프 · 실적 표에서 켜고 끄기). `유형별`(기본) = 지표 하나를 골라 합계 + 유형마다 그래프 한 장(개별 / 같은 눈금), `지표별` = 유형 하나를 골라 지표 14개(광고비 · UV · 비회원UV · 가입 · 가입CPA · 가입률 · 첫구매객수 · 첫구매CPA · 첫구매거래액 · 첫구매율 · 신규고객수 · 신규거래액 · 순결제거래액 · 순결제 ROAS). 비교를 `선택`으로 두면 흐름 · 표가 실적기간 vs 비교기간(날짜 순서끼리)으로 바뀜 · 그래프 아래 **메모**(리뷰 · 계획 두 칸, 서식 · 색, 기간 · 필터에 붙이고 📌 로 이동, 이 브라우저에 저장 · 백업 내려받기에 함께 담기고 백업을 열면 합쳐짐) | 로우 |
| **드릴다운** | 유형 › 매체 › 비용출처 › 브랜드/기획전 › 캠페인 › 하위캠페인 › 디바이스 중 원하는 순서로 최대 5단계. 현재 vs 비교 기간 증감, 검색, 정렬(기본 = 광고유형은 브랜드검색광고 › 사이트검색광고 › 쇼핑검색광고 › DA › DA(페이먼츠) › 메시지 › PA 순, 그 외 단계는 신규거래액 큰 순). 이름을 누르면 그 항목의 지표 9개 추이(점선 = 전년) | 로우 |
| **첫구매 진단** | 지표 카드 16개(추이 지표 · 구매고객 · 첫구매 전환율)의 베이스라인 대비 · 계절요일보정 대비, 진단(계절요일보정 대비 차이를 객수 × 객단가 · UV × 전환율 · 가입 × 첫구매율 등 요인으로 나눠 주원인 표시, 첫구매거래액 · 신규거래액이 늘고 준 매체 · 캠페인, 효율, 직접 편집 · 저장, 작은 '계산 방식' 링크), 단계 선택 드릴다운(디바이스 포함, 표 지표 선택 — 기본 첫구매거래액 · 신규거래액), 구성 효과 분해(기준 지표 첫구매거래액 · 신규거래액 · 첫구매객수, 브랜드/기획전 · 캠페인 · 디바이스 등 구성 기준, 시즌 항목 포함/제외, 계절요일보정 대비), 원천 · 구간은 맨 아래 | 로우 |

공통: 월별 · 주별 · 일별, 일평균 · 누계, 전년 동기간 · 전기 비교, 기준 기간 · 범위, 광고유형 · 비용출처 필터, 쿠폰 이벤트 표시. 보기 설정은 브라우저(localStorage)에 남는다.

## 배포

Streamlit Cloud → New app → 이 저장소 · Branch `main` · **Main file path `app.py`**. 보는 사람을 제한하려면 앱 Settings → Sharing에서 이메일 초대. 로컬 실행: `python -m streamlit run app.py`.

## 파일

| 파일 | 역할 |
|---|---|
| `dashboard.html` | 화면 · 상태 · 차트 · 표 |
| `calc.js` | 공식 산식(기간 · 일평균 · CPA · 비교 기간 · 드릴다운 트리 · 베이스라인 · 구성 효과 분해). 화면과 테스트가 함께 쓴다 |
| `build_data.py` | 원천 → 백업, 광고유형 분류, 이어 붙이기 |
| `make_backup.bat` | PC(윈도우)에서 더블클릭 — `raw` 폴더 원천으로 백업 만들기 |
| `update.bat` | PC(윈도우)에서 더블클릭 — GitHub `main`의 최신 프로그램 파일(build_data.py · make_backup.bat · calc.js · dashboard.html 등)로 바꾼다. `raw` · `backup` · `data` 폴더는 건드리지 않는다. 하나라도 못 받으면 아무것도 바꾸지 않는다 |
| `app.py` | Streamlit: `dashboard.html` + `calc.js` 를 화면 가득 표시 (업로드 없음) |
| `tests/` | `make_sample.py`(가짜 원천, 임의값) · `test_build.py` · `test_calc.mjs` · `test_real_numbers.py`(실데이터 + 로컬 기대값이 있을 때만) |
| `docs/METRICS.md` | 지표 · 분류 · 기간 정의, 분석 원칙 |
| `docs/HANDOFF.md` | 배경 · 분석 맥락 · 다음 과제 |

## 검증

```bash
python -m pytest -q tests          # 빌드 · 분류 · 이어 붙이기
node --test tests/*.mjs            # 화면 산식
python -c "from streamlit.testing.v1 import AppTest; at=AppTest.from_file('app.py'); at.run(); print(at.exception or 'OK')"
```

실제 수치 대조는 `raw/` 폴더에 원천을 넣고 `tests/local/expected.json`(형식은 `tests/test_real_numbers.py` 주석)을 만들어 `pytest`를 돌린다. **공개 저장소이므로 원천 · 백업 · 실제 수치는 커밋하지 않는다**(`.gitignore`: `raw/` · `data/` · `backup/` · xlsb/xlsx/csv · `.json.gz` · `tests/local/`).
