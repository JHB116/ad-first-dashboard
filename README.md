# 광고 신규 실적 대시보드

LF몰 **광고유형별 신규(가입)·첫구매 실적**을 깊게 보는 대시보드다. 전체 채널 관점의 [첫구매 실적 대시보드](https://github.com/ryunj/first-dashboard)와 같은 틀(정적 HTML 한 장 + Streamlit 래퍼 + 브라우저에 여는 백업 파일)을 쓰고, 광고 실적만 유형 → 매체 → 캠페인 단위로 파고든다.

**저장소에는 실적 데이터가 없다.** 원천 파일로 백업(`.json.gz`)을 만들어 화면에서 연다. 열어 둔 데이터는 그 브라우저(IndexedDB)에만 저장된다.

## 원천 형식

| 원천 | 형식 | 비고 |
|---|---|---|
| **로우 시트 xlsb** | 시트 이름 `로우`, 첫 행 헤더 (`기간_일자`, `구분_광고유형`, `구분_채널`, `구분_매체명`, `구분_비용출처`, `구분_캠페인`, `구분_하위캠페인`, `구분_브랜드/기획전`, `구분_디바이스`, `지표_광고비`, `지표_UV(전체)`, `지표_가입회원`, `지표_총결제고객수`, `지표_총결제거래액`, `지표_총결제고객수(첫구매)`, `지표_총결제거래액(첫구매)`, `지표_순결제고객수(첫구매)`, `지표_총결제고객수(윈백)`, `지표_당년신규순결제고객수`, `지표_당년신규순결제거래액`) | 일일보고서 xlsb 전체든 로우 시트만 뽑은 파일이든 같다. 다른 컬럼은 무시. 기간을 나눈 파일 여러 개 가능 |

원천은 이것 하나다. 첫구매 실적 대시보드의 원천 형식과는 무관하다. 계절 비교(전년 같은 구간)는 로우에 그 해 데이터가 있어야 계산된다.

## 백업 만들기 · 갱신

### A. Streamlit 화면에서 (권장)

1. 대시보드 맨 위 **📂 원천 파일로 백업 만들기 · 새 날짜 추가**를 연다.
2. 로우 시트 xlsb(여러 개 가능)를 올린다. 이어 붙일 때는 **기존 백업**도 같이 올린다.
3. **백업 만들기** → 아래 대시보드에 바로 열리고, **백업 내려받기**로 파일을 받아 둔다(다음 갱신 때 '기존 백업'으로 올림).

- 같은 날짜는 새 파일 값으로 교체된다. 파일 여러 개에 같은 날짜가 있으면 뒤에 올린 파일이 이긴다.
- 올린 원천은 서버에 저장하지 않는다(임시 폴더에서 읽고 바로 지움). 업로드 한도 500MB(`.streamlit/config.toml`).
- 전체 기간 xlsb처럼 큰 파일은 몇 분 걸리고 서버 메모리를 많이 쓴다. 매일 그날치 로우만 이어 붙이는 방식이 가볍다.

### B. 로컬에서

```bash
python -m pip install -r requirements.txt
python build_data.py                                   # data/raw/ 의 *.xlsb 전부(수정시각 순)
python build_data.py --base backup/기존.json.gz --row data/raw/1001.xlsb   # 이어 붙이기
python build_data.py --lite                            # 하위캠페인 · 브랜드/기획전 · 디바이스 차원 제외(가볍게)
# → backup/광고신규대시보드_백업_YYYYMMDD.json.gz
```

## 화면

| 메뉴 | 내용 | 출처 |
|---|---|---|
| **유형별 추이** | 지표 8개(광고비 · 가입 · 가입CPA · 첫구매 · 첫구매CPA · 첫구매거래액 · 신규구매자 · 신규거래액)를 위에서 아래로. `Total` = 한 그래프에 7개 유형 + 합계(범례 눌러 켜고 끄기), `유형별` = 유형별 소형 그래프 · 전기비/전년비. 요약 타일, 기간별 표(CSV) | 로우 |
| **광고 드릴다운** | 유형 › 매체 › 비용출처 › 브랜드/기획전 › 캠페인 › 하위캠페인 › 디바이스 중 원하는 순서로 최대 5단계. 현재 vs 비교 기간 증감, 검색, 정렬. 이름을 누르면 그 항목의 지표 9개 추이(점선 = 전년) | 로우 |
| **DA 가입 분해** | DA 전체 / 테스트 캠페인 / 테스트 제외, 테스트 매체 · 카카오 신규고객확대 포함 여부 선택, 테스트 캠페인 상세 | 로우 |
| **첫구매 진단** | 구매고객 · 첫구매 · 첫구매 비중(첫구매 ÷ 구매고객) · UV · 첫구매 전환율(첫구매 ÷ UV)의 베이스라인 대비 최근(계절 기대치 · 요일 보정 · 판정 문구), 첫구매 변화 = 유입 × 전환율, 연도별 월 비교, 단계 선택 드릴다운(디바이스 포함), 구성 효과 분해(브랜드/기획전 · 캠페인 · 디바이스 등 기준 선택, 시즌 항목 포함/제외) | 로우 |

공통: 월별 · 주별 · 일별, 일평균 · 누계, 전년 동기간 · 전기 비교, 기준 기간 · 범위, 광고유형 · 비용출처 필터, 쿠폰 이벤트 표시. 보기 설정은 브라우저(localStorage)에 남는다.

## 배포

Streamlit Cloud → New app → 이 저장소 · Branch `main` · **Main file path `app.py`**. 보는 사람을 제한하려면 앱 Settings → Sharing에서 이메일 초대. 로컬 실행: `python -m streamlit run app.py`.

## 파일

| 파일 | 역할 |
|---|---|
| `dashboard.html` | 화면 · 상태 · 차트 · 표 |
| `calc.js` | 공식 산식(기간 · 일평균 · CPA · 비교 기간 · 드릴다운 트리 · 베이스라인 · 구성 효과 분해). 화면과 테스트가 함께 쓴다 |
| `build_data.py` | 원천 → 백업, 광고유형 분류, 이어 붙이기 |
| `app.py` | Streamlit: 원천 업로드 → 백업, `dashboard.html` + `calc.js` 표시 |
| `tests/` | `make_sample.py`(가짜 원천, 임의값) · `test_build.py` · `test_calc.mjs` · `test_real_numbers.py`(실데이터 + 로컬 기대값이 있을 때만) |
| `docs/METRICS.md` | 지표 · 분류 · 기간 정의, 분석 원칙 |
| `docs/HANDOFF.md` | 배경 · 분석 맥락 · 다음 과제 |

## 검증

```bash
python -m pytest -q tests          # 빌드 · 분류 · 이어 붙이기
node --test tests/*.mjs            # 화면 산식
python -c "from streamlit.testing.v1 import AppTest; at=AppTest.from_file('app.py'); at.run(); print(at.exception or 'OK')"
```

실제 수치 대조는 `data/raw/`에 원천을 넣고 `tests/local/expected.json`(형식은 `tests/test_real_numbers.py` 주석)을 만들어 `pytest`를 돌린다. **공개 저장소이므로 원천 · 백업 · 실제 수치는 커밋하지 않는다**(`.gitignore`: `data/` · `backup/` · xlsb/xlsx/csv · `.json.gz` · `tests/local/`).
